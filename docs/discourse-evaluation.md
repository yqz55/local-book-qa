# 短文章原因与方法问答验收

这组材料检查确定性原因／方法问答的完整路径：自然问题 → 内容词检索 → 相邻句窗口 → 原句候选 → 显式关系抽取 → 证据分组 → 原文字段模板。它是可逐题人工检查的固定实现验收集，不能据此声称系统理解任意文章、能处理整本书，或取得开放问答准确率。

## 材料

`data/discourse_articles/` 有 28 篇明确标为原创测试短文的材料，每篇至少有三条完整句子，构造场馆记录、项目调整和调查纪要等短文章场景。这些材料不是网页摘录，不表示真实事件；原创声明、编写日期、文件字节长度和 SHA-256 在 `sources.json` 中。标题、声明和日期不会加入检索正文。

另外复用 `data/articles/` 已归档的 3 条公开原句。复制后的 TXT 与旧文件逐字节相同；未增加正文信息，也未为本次评估重新访问网页。来源和先前核对日期仍以旧清单为准：

|---|---|---|---|

## 36 个固定问题

问题保存在 `cases.json`，包含“为什么会延期启动”“暂停开放是什么原因”“怎样才能完成土壤调查”等自然表达。每题注明目的、期望状态、需要命中的完整原句，以及适用时的精确字段、跨句绑定或证据组角色。

| 类别 | 固定检查 |
|---|---|
| 明确原因 | 因为 C 所以 E、由于 C，E、E 的原因是 C、C 导致 E；仅在所问结果匹配时提取 C |
| 因果方向与否定 | 不把结果倒推为原因；原因内部的“未及时接通”保持原样；否定因果关系不输出肯定原因 |
| 事实状态与对象 | 目的、未来安排、假设、引语和另一对象的原因不能当成所问事实；不忽略夜间／白天条件 |
| 明确方法 | X 通过／采用 M 完成 Y、X 完成 Y 的方法是 M；提取原文 M 并核对 X 与 Y |
| 明确程序 | “要完成 Y，可以通过 M”回答怎样才能完成 Y；保留“可以”与完整作业说明，不改写为完成事实 |
| 方法的边界 | 计划、未完成、作业提示、引语、另一小组的方法和并列归档活动不证明所问完成方法 |
| 多句解释 | E。原因是 C。使用两条各自独立的原文区间；首句为关联支持，第二句为直接原因证据 |
| 排版一致性 | 相同三句话分别同行／分行保存，答案相同，句子仍各自定位 |
| 候选冲突 | 同一结果的两个不同原因、同一目标的两个不同方法均返回歧义，保留两份证明 |
| 缺少内容 | 只有“为什么会这样”“怎样才能这样”时返回 `no_content` |

清单中的 `not_answered` 是验收断言，表示允许 `evidence_only`、`unsupported` 或 `insufficient_evidence` 之一，且不允许事实字段；它不是新增的引擎状态。明确正例必须为 `answered`，冲突必须为 `ambiguous`，缺少对象必须为 `no_content`。没有把应能回答的显式关系改成保守拒答来提高通过率。

## 可检查的证明

评估器先验证精确 TXT 字节与来源清单一致，再逐题检查：

- 所需原因／方法是清单指定的原文文本，所有返回字段与其来源／清洗坐标一致，且位于相应的候选原句内。
- 所注明的完整原句均进入本次候选范围；疑问表达不作为普通检索关键词。
- 已回答的字段由通过的抽取决策和答案证明组覆盖；答案严格等于当前模板填入原文字段的结果。
- 跨句绑定及抽取决策中的区间可映射回各自原句；证据组逐句记录真实区间，直接／支持／上下文角色与清单一致。
- 冲突保留两个不同字段候选及其证明组，不选择第一条；重复窗口不生成重复原句集合的组。
- 所有非回答状态没有肯定事实字段。

JSON 报告保留每项布尔检查、问题解析决策、抽取决策、模板、字段与跨句绑定、候选原句、窗口统计、证据组及其角色，并记录引擎版本、原文字节、问答规则、窗口、词典和 WordNet 哈希，便于定位一次具体运行。

## 复跑

在项目根目录运行：

```powershell
python -m pytest tests/test_discourse_articles.py --basetemp=.data/pytest-discourse -q
python -m evidence.evaluate_discourse --output .data/discourse-evaluation.json
```

CLI 默认读取这份固定材料；`--fixtures` 可指定具有相同清单结构的目录。标准输出逐题列出通过情况、状态、字段和失败检查，最后列出正例、负例、原句命中及状态计数。`--output` 保存完整 JSON。退出码 0 表示固定检查全部通过，1 表示至少一项失败。报告中的数量描述这份验收集本身，不能外推成开放文章理解能力。

2026-10-18 的固定运行结果为 36/36 题通过：字段正例 14/14，其余拒答、歧义和缺少内容检查 22/22；32 题注明的完整原句集合全部进入候选。状态计数为 `answered=14`、`evidence_only=18`、`ambiguous=2`、`no_content=2`。包括清单完整性、区间／证明检查和 CLI JSON 写出的测试文件共 41 项通过。完整逐题结果由上述命令写入 `.data/discourse-evaluation.json`。

同一版本的全量回归为 565 项通过，原有 26 题窗口验收仍为 26/26。冻结的 1.7 记录按原算法复算，并已核对升级到 1.8 后重新生成的原因答案；两版对比中的上一版（1.6）对原因／方法问题不填入字段。上述数字只描述这份固定验收集和回归范围，不外推为开放文章理解能力。

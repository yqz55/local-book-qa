# 通用回答（1.9）

所有问题均可提交。系统提供与证据支持程度对应的响应，不保证任意输入都能从当前文本中得到事实结论。整个流程继续在本机运行，不调用模型或外部服务。

## 回答方式

| 界面结果 | 含义 | 数据记录 |
| --- | --- | --- |
| 已形成规则答案 | 专用字段或通用结构通过检查，输出原文字段 | `status=answered`；`mode=extracted/general` |
| 已形成原句答案 | 对象、属性或事件结构匹配，使用完整原句作答 | `status=answered`；`mode=excerpt` |
| 原文参考回答 | 已提供实际原文；未证明它完整回答了问题 | `status=evidence_only`；`mode=reference`；`fields` 为空 |
| 歧义 | 候选字段不唯一，或同一事实还有否定/非事实表达 | `status=ambiguous` |
| 证据不足／缺少内容 | 没有可引用命中，或问题没有可定位对象 | `insufficient_evidence/no_content` |

参考回答不计入已回答数量。概括、启示、评价、比较、判断和复合问题均可以得到相关原文参考，但系统不会把摘录改写成未经证据支持的总结、是非判断或因果结论。

## 通用结构

问题计划保留原来的分词和位置，新增 `question.answer_plan`：待答字段、已知对象/谓词/属性、作者评价归属、疑问槽位及规则。规则表和全部模式一同嵌入索引的 `answering.general_answers`，结果另存 `general_answer_policy`。

| 需求 | 问法示例 | 支持的原文结构 |
| --- | --- | --- |
| 身份或评价对象 | 谁是班长；作者认为谁是最可爱的人 | A是B、B是A；同句前置名词话题及明确评价归属 |
| 行为角色 | 谁发现了青霉素；张衡发明了什么 | 已知表达前后夹住待答字段；谓词不限定为赠送 |
| 主动/被动改写 | 青霉素是谁发现的 | A发现了B、B由A发现等显式角色对应 |
| 属性 | 盒子的颜色是什么；盒子是什么颜色 | 对象的属性是/为/包括/有某值 |
| 地点 | 研究所在哪里；会议在哪里举办 | 对象位于某地、对象在某地举办等 |
| 作用或结果 | 这个连重要的贡献是什么 | 对象明确，原句有对应属性或显式结果表达，引用整个原句 |
| 状态描述 | 遗体保持着怎样的姿势 | 对象明确，状态谓词与被问属性同句绑定，引用完整原句 |
| 行为概括 | 研究所做了什么 | 明确主语加带时态/完成标记的动作原句 |

通用结构仍有边界：已知关系和角色必须由原文语序或明确句式证明，不采用“找一个附近的人名/数字”作答。原因、方法、时间、数值和赠送沿用专门验证，通用抽取不能绕过其角色、因果方向、单位和状态检查。

作者评价以 `statement_kind=opinion` 保存。原文的“我感到”和“我们的战士→他们”分别有来源字段及绑定区间，不把其他人物的观点归给作者。同句指代规则只支持紧邻的明确名词话题，存在不明确前件时保留参考。

## 参考材料与来源

参考回答最多展示三条去重原文，优先保留相关的陈述句，过滤相对覆盖较弱的尾部命中。它引用真实来源区间，保留否定、引语、计划和不完整状态。

原因/方法问答还可以展示命中句之后的相邻引语，帮助保留人物自己的解释。这些引语标为 `origin=adjacent_reference_only`，记录在 `reference_context_ids`，不冒充检索命中或字段绑定证明；不跨章节、标题、列表或未覆盖的非空文本。可在“原文参考的逐条出处”查看。

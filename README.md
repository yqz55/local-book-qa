# 中文文本本地检索与规则问答

把中文 TXT 转为有来源、可核对、可复算的 BM25 检索证据和规则答案。所有文本处理和检索在本机完成，无模型、API Key、外部服务或运行时下载。界面提供导入、提问、通用词义扩展、原文定位、计算展开和记录复算。

当前 1.10 在通用回答基础上修复数量及复合单位、同句分句间对象绑定、事实约束核验和自然问法的字段识别。支持身份与评价对象、显式行为角色、属性、地点、作用/结果、状态描述、时间、数量、赠送及原文明示的原因与方法答案。通过结构和出处检查时给短答或完整原句；无法验证完整结论时给带出处的原文参考回答；没有命中或缺少对象时明确说明。开放式文学分析和隐含推理仍不保证能形成结论。PDF、TF-IDF/RRF 仍为后续设计。规则及边界见 [通用回答说明](docs/general-answers.md)。

## 启动

需要 Python 3.11 或更高版本。在项目目录执行：

```powershell
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

依赖已经安装时可直接运行 `./start.ps1`。打开 http://127.0.0.1:8501 。服务仅监听本机回环地址，关闭 Streamlit 使用启动终端的 Ctrl+C。安装依赖后运行不需要联网；Streamlit 使用统计已禁用，界面字体使用本机字体。

### Docker / 飞牛 NAS 部署

宿主端口 `10203` 的容器化部署见 [飞牛部署说明](docs/deploy-fnos.md)：镜像是官方 `python:3.13-slim`
（索引标识记录 `unicode_version`，需与实际生成记录的 3.13 / Unicode 15.1.0 一致），容器入口在首次启动时
把依赖装进持久卷，之后启动不需要联网；对话、索引与复算记录保存在宿主的
`/vol2/1000/nlp/data`，重建容器不会丢失。仓库根目录的 `Dockerfile` 与 `docker-compose.yml`
给出等价的镜像构建方式。

1. 点击“新建对话”，上传一份 TXT。文件上传后自动清洗、分词、建立索引，并给出简短处理说明；不生成内容摘要。优先严格解码为 UTF-8，失败后尝试严格 GB18030，均失败时明确报错；不会使用替代字符。可在高级工具中手动指定编码。
2. 在底部输入框提问，按 Enter 发送（Shift+Enter 换行）。回答默认只显示答案，每次提问独立检索当前文档，不依赖前文。底部附件可提交另一份 TXT，始终新建对话；同时输入的问题会针对新文件检索。
3. 每条回答的“查看算法过程”默认折叠，展开后依次查看问题分词、实际检索词及扩展、候选窗口与 BM25 逐词计分、原文证据及答案形成规则。显示的数据来自该次实际查询；完整快照仍可独立复算。
4. 左侧按文件保留对话，切换和重新打开页面会恢复历史。同一文件重复上传也会创建独立对话。右上角菜单支持重命名、导出 TXT、清空当前问答及删除；删除后可在当前会话撤销。索引和复算记录独立保留，不受清空或删除对话影响。
5. 左侧“高级工具”保留第一版完整工作台：两版对比、文本与索引、词典及关系校正、记录导出和复算。也可从某条回答展开区进入该次完整记录。默认聊天仅运行当前版，进入高级工具时才按需生成上一版对比。原有已保存文本可在高级工具中选择，再点击“用当前文本新建对话”；同文档的词典调整在返回时保留已有聊天，旧回答仍对应各自原始快照。

对话保存在 `.data/conversations/`，完整索引与查询快照分别位于 `.data/indexes/` 和 `.data/traces/`。界面采用白色聊天区、浅灰侧栏和固定底部输入框，手机上可通过左上角按钮打开历史列表。原问答引擎、CLI 与历史复算格式保持兼容。

导入时先从**整本书发现姓名和人物称呼**，默认没有预填的人名或别名组。规则使用姓氏与复姓结构、人物说话/动作、姓名介绍、姓氏与称谓等上下文；普通词、称谓本身和语法片段会被排除。非姓氏名称通常需要至少 2 次原文出现、2 处独立人物上下文；有姓氏结构及有效人物上下文或原文明示介绍时可接受较少出现的名称。候选限定 2–4 个汉字，单字简称不自动关联。完整规则、资源、阈值、接受/拒绝判断和原文位置均写入索引。

基础分词使用固定版本 `jieba==0.42.1` 的通用词典数据（348,974 个汉字词条，包含正常单字词），采用本项目可追踪的 DAG 动态规划实现，关闭 HMM。先保护已发现姓名及用户补充的本书专用词条，再对其他连续汉字构建候选词图，选择整段总分最高的不重叠路径。它会比较完整切分组合；正常单字词和未登录单字回退分别标记。纯汉字段的无书内奖励基线已与 jieba 精确模式 `HMM=False` 对照。

导入分两遍：第一遍仅用通用词典与保护词分词，统计初分词频；第二遍给多字词加入有上限的书内奖励（默认最多 0.25），生成正式分词和索引。词典频次与初分词频分别保存，奖励公式公开。**正文和查询共用同一份冻结配置**，提问不会重估词频或改变词典。

姓名识别与人物关联分开处理：去姓得到的二字简称须有独立出现和人物上下文，而且本书只有一个候选全名，才能自动关联；“又名、字、号、姓…名…”等明确介绍也可提供关系。一个简称对应多个全名时保留歧义，不自动合并。

问题中的名称按已接受的同一人物组双向展开一层。原词与扩展词取并集，每个不同词项的 BM25 权重为 1；重复出现、重复展开不重复加权。正文仅统计实际出现的不重叠词项，全名内部的简称不重复计 TF。“姓…名…”构造的规范全名若没有连续出现在正文中，TF 为 0，检索由实际出现的称呼提供证据。

通用表达扩展使用随项目附带的 **Chinese Open Wordnet** 固定数据版本，不需要为每本书手工建立同义表，也不需要安装 NLTK 或联网下载。原始数据、许可证和来源哈希保存在 `data/wordnet/`；从中保留 2–32 字汉字表达、至少两个有效表达的词义组。当前归一化资源共 14,259 组（含 1 组项目通用校正）、29,993 个不同表达。原始词义编号与词性分别保留，不把多义词的各个词义递归合并。

例如输入“计算机”可召回实际写着“电脑”的段落。`data/query_expansion_overrides.json` 另存“赠送 / 赠与 / 送给”的通用校正，标注为项目审核来源，不冒充 WordNet 原始关系。通用校正暂停与其表达相交的原始组；本书人工校正再覆盖相交的通用组，避免传递关联。候选是检索线索，不表示上下文词义、人物角色、否定和事实状态已经确定；答案层另用明确句式、角色、状态和字段来源检查。

扩展只从问题实际出现的完整词项或连续短语展开一层，姓名、语法/否定/状态词和本书停用表达不参与扩展。仅保留在本书词项边界连续出现的候选，不能在长词或姓名内部命中，也不跨标点、空白。独立的表达匹配表允许“送给”在正文被分为“送 / 给”时仍按连续短语命中；短语 TF/DF 和出处单独记录，主索引 TF、段长及分词不变。问题中被完整短语覆盖且没有独立出现的碎片不另计分。

默认仅语义扩展的表达权重为 `0.7`（配置参数，不是正确概率），每个问题表达最多 3 个候选，每题最多处理 12 个表达。候选先按本书人工、项目校正、WordNet 来源排序，再按共享词义数、本书 DF、表达长度降序、文字升序筛选。同一计分组每段只取最大加权 BM25 贡献，同分按查询特征顺序，避免同义表述堆叠加分。多义候选的词义编号与未消歧状态、未采用候选及原因一并展示。

在“文本与索引 → 通用词义扩展与本书校正”可开关扩展、修改权重/数量、填写本书表达组或停用表达。保存后产生新版本并清空旧结果，复用既有分词与主索引；修改人物关系或专用词条时保留表达设置。校正默认空白，按书隔离，可导出 JSON。清空本书校正恢复通用关系；停用表达既不触发展开，也不作为新增候选，但仍可按问题原词检索。

“文本与索引 → 本书姓名与称呼（自动发现）”可筛选已接受或未接受的候选，核对原文位置、判断规则、自动关系及歧义。“检索证据 → 查看查询分词与检索规则”显示实际分词、选择依据、关系来源和原文证据。所有扩展词没有虚构的问题位置。规则是确定性的启发式，可能漏收或误收；称谓及同名人物尤其需要核对，不能把自动关系当作事实断言。

如果人名或术语切错，进入“文本与索引 → 本书专用词条（补充后重建）”，每行填写一个 2–32 字汉字词，点击“应用词条并重建索引”。系统保留原始文件和基础词典，合并这些词条后重新分词、统计与建立索引，并清空旧查询结果。删除一行可移除该专用词条；旧索引、旧查询记录仍保留。专用词条支持导出为 JSON，按书独立保存。

“文本与索引 → 人工关系校正（可选）”默认空白。需要修正规则关联时，可每行用 `=` 分隔同一人物的名称，再点击“应用别名并重建索引”。人工组另存来源，并暂停与其名称相交的自动组，避免意外传递合并；清空人工组后恢复自动关系。人工校正不作为姓名发现的种子。应用旧版本书籍时会从保存的原始字节重建为新索引，旧记录按原规则继续复算。

首次打开提供随程序附带的演示文本；它是演示资料。导入后切换到自己的文件。索引、历史和参数快照写入 `.data/indexes/` 与 `.data/traces/`，重新启动可以从已保存书籍中选择。可用环境变量 `NLP_DATA_DIR` 更换存储目录。

## 明确规则

| 环节 | 实际规则 |
| --- | --- |
| 清洗 C001–C004 | 删除文件开头 BOM；CRLF/CR 转 LF；删除行首尾 ASCII 空格/TAB/全角空格；段内 TAB/全角空格各转一个 ASCII 空格。保留内部连续空格、数值、否定词和可见符号。每次修改保存原区间、前后文字与规则编号。 |
| 切分 S001–S005 | 空白行不生成段落；每个非空物理行独立处理，不合并折行。短章节标题单独保留，并传递章节标记。默认每段最多 400 个 Unicode 字符，超长时在上限内最后一个 `。！？；.!?;…` 后切分，没有标点则硬切。无重叠，不丢失行内字符。 |
| 姓名发现 N101–N109 | 从全书的姓氏结构、介绍句、说话和动作等上下文提出 2–4 字候选，检查边界、普通词和语法片段，保存所有候选及接受/拒绝依据。姓氏、称谓和语法词是通用语言资源，没有人物名单或书籍名单。 |
| 人物关系 N201–N203 | 唯一全名与独立二字简称、或明确的同一人物介绍可关联；共享简称保留歧义。姓氏称谓不与普通称谓直接合并，不猜测单字称呼。 |
| 正文与查询 D001–D005、N001 | 使用相同清洗、完整词典、姓名与专用词保护、DAG 路径评分和冻结的初分词频。词典无候选才加入单字回退边；正常单字词仍可作为词典词项。路径同分时当前位置较长词优先。 |
| 路径评分 D003–D004 | 边分 = ln(max(词典频次,1)/词典总频次) + 书内奖励；未登录词原词典频次为 0，路径计算按 1 回退。多字词奖励 = 上限 × ln(1+初分词频)/ln(1+全书最高初分词频)，单字奖励为 0。最大频次为 0 时分母固定为 1。从句尾记录每个位置的候选、边分、后续最优分与胜出路径。 |
| 字符规则 T003–T005 | ASCII 字母/数字与内部 `._+-` 连成词，字母转小写；其余 Unicode 字母、数字、组合标记、符号逐个成词。空白、标点和控制/格式字符跳过且记录。 |
| 扩展 A002–A004 | 按已接受关系双向展开一层，自动/人工来源分别记录。不同词项权重为 1，重复扩展不重复计分，不虚构查询位置或正文 TF。 |
| 词义扩展 E001–E006 | 通用词义组加来源明确的校正，仅一层、按书筛选、限制数量。原词权重 1，语义新增表达默认 0.7；同组取最大贡献。连续表达区间单列，问题原位置与新增候选分开记录。 |
| 统计 | TF 为段内出现次数，DF 为包含该词的检索段落数，段长为分词后词项数量。N 和 avgdl 仅使用有词项的段落；只有标点的段落保留位置但不计 N。保存全书 TF、DF、各段 TF、段长与倒排列表。 |
| 候选与排序 | 候选为有效问题词项及通过筛选的扩展表达倒排并集。无实际计分匹配的段落不返回。按未舍入总分降序，再按原文起点和段落编号升序。 |
| 原因 D101–D104 | 只从原文明确因果句抽取原因；绑定问题所问结果，保留因果方向和原因内部否定，不把目的、计划、传闻或时间先后当作事实原因。 |
| 方法 D201–D204 | 只从明确方法句抽取方法；核对施事、结果、方法边界和处方情态，步骤说明不写成已完成事实。 |
| 原因/方法拒绝 DG101–DG103 | 引语、传闻、推测、计划、未来、假设、否定因果、泛指代、跨边界和多个不同候选时不强选；保留原文与逐项拒答原因。 |

机器记录中的区间统一为 **Unicode 字符、0 起点、左闭右开** `[start, end)`，不是字节或 UTF-16 编码单元。界面行列号及“字符 a–b”为 1 起点、包含末字符。CRLF 算一个物理换行；压缩区间映射保留它在原文中的两个字符。段落原文范围覆盖该段保留内容，删除的行首尾空白仍在完整原文、源字节和清洗日志中。

`data/dictionary.json` 现在是项目补充词条，仅允许 2–32 字的纯汉字词。侧栏上传的 JSON 替换这一小份补充词条，完整通用词典始终启用。需要保证完整匹配的专业词可加入“本书专用词条”。通用词典、补充词条、初分词频、姓名发现与关系分别版本化；姓名发现仍不依赖通用词典的人名作为种子。未知词仍可能回退，可检查依据并按书补充。词义扩展使用独立表达匹配表；字符二元组尚未加入。主索引只统计实际、不重叠的分词，避免混淆段长和 TF。

## 通用回答（1.10）

问题新增对象、谓词、属性、待答字段与评价归属计划。身份、通用行为角色、主动/被动改写、属性和地点可以生成字段答案；作用、结果、状态描述与行为概括可引用完整原句。通用角色的谓词来自问题和原文，不再限定为赠送。

未能验证字段的开放问法仍会输出实际原文参考，并展示未解决条件和逐条出处。相邻引语只作为明确标记的参考上下文；不冒充检索命中或已证明的事实关联。参考回答不计入已回答数量。完整结构、示例与限制见 [通用回答说明](docs/general-answers.md)。

## 前端版本对比

2026-10-18 增加两版对比入口。“检索证据 → 版本对比”默认并排显示“上一版 · 段落召回与单句答案”（冻结的 1.6 算法）和“当前版 · 窗口召回与多句答案”（1.10 算法），也可选择只看一版。一次点击“检索”运行两版，切换显示方式复用同一次结果，不重复检索。

上一版独立从当前资料保存的原始字节、编码、词典、冻结分词配置、姓名/人工关系和表达校正建立历史索引，再实际运行旧算法。它不使用当前版窗口、两句关联或原因／方法抽取结果。对比前逐项核对两版的来源、分词、姓名、表达设置、问题和 BM25 参数。两版各自的原文、字段、拒答原因、候选及计算明细都可查看；检索单位不同，因此分数不直接横向比较。原因与方法问题上，上一版只会给出“暂不支持该问题类型”或关键词证据，不会填入原因／方法字段。

“导出上一版复算记录”和“导出当前版复算记录”分别生成可独立复算的 `/7` 与 `/11` 文件。本地历史记录标明引擎版本。导入其他文本、修改专用词条、别名或表达设置会一起清空两版结果；旧索引和旧记录仍保留。上一版对比索引按当前索引标识缓存，不改变当前活动资料。

## 相邻句窗口与多句证据（1.7）

原始行、原始段落、句子、召回窗口和答案证据分别保存。窗口不改变原文，不把多个物理行拼成虚构句子。原始段落索引继续保留，供历史兼容与诊断；当前规则答案使用新的窗口召回范围。

`CW001–CW008` 为每句保留一个检索单位，并生成可跨普通换行或空行的连续 2–4 句窗口，默认最多 600 个清洗后字符。长单句单独保留全文。章节、被省略的非空标题、短独立未终止小标题、列表条目边缘、引语和不完整片段阻止跨越；同一列表项内部的完整句仍可形成窗口。这些是显式格式规则，不能识别所有语义话题切换。无法确定的折行仍保留片段，不猜测补全。

窗口复用正文实际词项区间，不重新分词；窗口词项只保存轻量位置，完整分词解释仍在原始段落。每个实际词项出现只在每个窗口中计一次。重叠窗口各自作为文档，独立生成 `N/TF/DF/avgdl`，并采用同一 BM25 公式；窗口 DF、段长及分数不与原始段落混用。短语只继承原索引中实际连续的词项区间，不能通过跨行或跨句连接制造短语。

检索返回 `window_retrieval`，旧的 `candidates/top_ids/corpus` 保留为原始段落诊断。句子筛选与问答使用窗口前 20 名的全部子句，含零单句匹配的邻句。`evidence_groups` 按句子 ID、原文区间去重，并对每个查询概念只取最高覆盖值；不会把多个重叠窗口的 BM25 分数累加成证据强度。单句充分时保留最小单句证据；需要两句时分别引用。追加邻句需要增加问题内容覆盖、重复明确对象或出现受支持的该X指称，并标为上下文；邻近本身不证明事实关联。

`J101/J102` 只支持以下相邻两句形式：前句以问题明确命名的唯一项目、试点、活动、实验或工程作为主语；后句以同类型的“该项目/该试点/该活动/该实验/该工程”开头，并用明确句式给出所问时间或数量。必须满足词项边界、唯一对象、同类型指称、相邻、无结构边界、肯定事实、字段唯一、事件或属性及指定单位一致等检查。保留原文数值、单位、近似、范围和日期限定，不补年份、不做隐式单位转换。存在多个对象、一般他/她/它、较远距离、引语或否定/计划时停止联合抽取。

两句答案保存对象字段、该X指称字段及时间/数量字段，各自引用实际原句；`answer.bindings` 保存前件、指称和检查结果。不同字段或相关否定证据阻止唯一答案，冲突时各组独立证据仍关联到答案。界面用“直接证据/关联证据/补充上下文”区分用途，每句保留行列与字符区间，非连续证据不会伪装成一句引用。窗口原句及计算明细可展开。

所有窗口、边界、统计、排名、组内贡献、纳入原因和关联证明均进入索引/记录并独立重做复算。1.6 的问题解析、句子、抽取和检索实现已经冻结；旧记录按原算法复算。核心 API `build_index(..., context_config=...)` 可配置最多句数和字符上限；配置改变索引标识，当前界面采用默认设置。固定短文章验收见 [测试材料与逐题检查](docs/article-evaluation.md)。

## 原文明示的原因与方法答案（1.8）

1.8 把“为什么／原因是什么”和“怎样／如何／用什么方法”从“只展示原文”扩展为受支持的模板答案，前提是原文自己写出了原因或方法。作者未写明的因果、目的、时间先后和常识补充都不生成原因；操作说明保留原文语气，不写成已经完成的事实。

问题侧沿用 `QP001–QP006`（`question-plan/2`），新增“原因是什么／原因有哪些／为什么会／为什么要”和“的方法是什么／方法是什么／通过什么方法／采用什么方法／怎样才能／如何才能／怎样操作／如何操作／怎样进行／怎么做”等完整问法。`才能／才可以`等只作问法标记，不参与内容计分；“怎样才能这样”只有指代和助动词时返回 `no_content`。疑问表达仍不参与检索与词义扩展。

`data/answer_templates.json` 的 `T106`（原因）与 `T107`（方法）只有 `reason`／`method` 必需字段。字段必须来自一条实际候选原句；模板只补充固定措辞，不添加原文没有的因果结论。

| 规则 | 实际条件 |
| --- | --- |
| D101 | `因为 C，所以 E`、`由于 C，E` 只在问题全部内容词按真实词项顺序绑定结果 E 时抽取原因 C。 |
| D102 | `E 的原因是 C`、`E 是因为／是由于 C`、`E，因为 C` 抽取原文原因 C；否定因果不改写成肯定原因。 |
| D103 | `C 导致／造成／致使 E` 按原因到结果的明确方向抽取 C；问题绑定 E 时不反向回答 C 的原因。 |
| D104 | 前句完整且精确绑定所问结果、紧邻后句以 `原因是／这是因为` 开头时联合引用两句；不跨章节、标题、列表或候选范围。 |
| D201 | `X 通过／采用／利用／使用 M 完成 Y` 只在施事与结果都和问题逐词绑定时抽取 M；方法与结果的边界来自真实词项区间。 |
| D202 | `X 的方法是／的方式是／的步骤是 M` 只提供原文操作说明，标为 `procedure`，不声称操作已经执行。 |
| D203 | `要 Y，可以通过 M`、`若要／如需 Y，应当采用 M` 保留原文处方、情态和完整句子；`为了` 只表示目的，不能当作事实原因。 |
| D204 | `……的方法如下／步骤如下／操作步骤如下` 加紧邻的 `首先……，然后……，最后……` 步骤句，最多两句；只在完整、无边界且前件精确绑定时引用。 |
| DG101 | 原因和方法都拒绝引语、传闻、推测、计划、未来、假设及否定因果；原因内部的“未及时接通”等否定原样保留；结果的否定或取消必须本身是问题所问事件。 |
| DG102 | 所有实质查询词、限定词、角色和 `已／曾／正在` 等状态须在正确的结果或方法角色中按真实词项顺序核验；不解析泛指代，不截取更长词项内部，不跨句边界。 |
| DG103 | 不同因果层、多个可选原因或不能唯一划定的方法边界不强选第一条；并列的明确原因保留为一个完整原文区间；不同字段候选返回歧义并分别保留证明。 |

只有必需字段、显式关系和角色检查都通过才填模板；不同表述、相反状态或不同原因返回 `ambiguous`，同时列出各自的抽取决策，不擅自合并或判定矛盾。事实答案标 `statement_kind = fact`；`要……可以／应当……` 这类原文处方标 `procedure`，字段逐项保留 `method`、`effect` 或 `target`、`subject`、`purpose`、`modality`、`prescription` 的原文区间。两句原因答案另存前件、`原因是` 承接表达、两句独立区间和关联检查；证据组把字段所在句标为直接证据，把对象关联句标为关联证据，补充句只作上下文。

界面在“答案字段与原文出处”逐项显示原文字符区间和高亮，并分别说明“原因关系取自原文明确表述”“步骤说明不代表这些操作已经执行”。索引、复算记录和 CLI 输出保存 `discourse_policy`、规则快照、逐条抽取决策、锚点区间、边界与拒答原因；复算会重新执行这些规则并比较字段、区间、方向和状态。固定材料与逐题检查见 [短文章原因与方法问答验收](docs/discourse-evaluation.md)。

1.7 的窗口、证据组、两句指代实现和 1.6 的实现已冻结为历史模块，旧记录按原算法复算；新查询升级到 1.8 并另存索引。

## 问题提炼、句子证据与第一版答案

输入问句先通过 `QP001–QP006` 生成问题计划，再进入 BM25。原始问题和完整分词始终保留；疑问表达、礼貌前缀和问句中的独立语法词不参与计分或词义扩展。引用的字面词、姓名和本书专用词受保护。“书中‘为什么’一词出现在哪里”仍能检索“为什么”。否定、计划、假设和指代等另存事实约束，时间和地点约束保留原位置。只有“为什么会这样”这类没有对象或事件的问题返回缺少内容。

句子表独立于 400 字检索切块，能恢复同一物理行中跨块的完整句子；标题不作答案。中文句末标点、末尾引号、小数、版本和常见缩写有明确规则。无终止符、复杂引语、省略号和排版断行保守标为片段，不猜测跨行合并。

从独立窗口 BM25 前 20 个候选取得全部子句，按句子 ID 去重；保留本句零关键词命中的邻句作为关联候选。按查询计分组计算每个概念的最高匹配权重，人物别名并入原词概念：`句子覆盖分 = 各概念最高匹配权重之和 / 概念数`。同分依次比较直接原词匹配数、原文位置、句子编号。每组匹配、真实区间和分数贡献全部保存；分数不是正确概率。默认展示 3 组证据，优先显示最终答案实际引用的原句及其对象关联；每句单独定位，并可查看完整候选。

| 问法 | 受支持的第一版条件 |
| --- | --- |
| X 是什么 | 明确的“X 是 / 是指 / 指 / 定义为”句式，引用完整原句。 |
| X 何时发生 | 同一分句中按实际词项边界和顺序绑定对象、事件，字段唯一。可以识别句首日期后接事件；不补原文没有的年份。 |
| X 有多少 | 同一分句绑定对象、属性；保留数值、单位、范围、符号和近似限定，核对问题明确要求的单位。不做隐式单位转换。 |
| 谁把 A 送给 B 等 | 受支持的显式赠送句式，逐一核对送出者、物品、接收者，仅抽取被问字段。 |
| 如何描述 X | 目标内容匹配后引用完整原句，固定模板组织。 |

原因与方法问法自 1.8 起使用上一节的显式关系规则；时间、数量和赠送继续使用专门验证。身份、属性、通用行为角色、地点、结果和状态描述自 1.9 起使用通用结构，未通过验证时返回原文参考回答。

事实短答拒绝不完整句、复杂引语、否定、计划、假设、疑问和传闻。未解决的指代、复杂施受事或人物歧义停止短答；现在额外支持下述严格的相邻两句对象关联，对其他事实约束继续保守提供原文。不同字段、多个无法绑定的时间或数量、相关非事实证据均可阻止唯一答案。检查仅限本次候选范围，未命中不代表全文不存在答案。规则是启发式，尚不能保证任意文章的语义理解。

`data/answer_templates.json` 定义固定模板，索引内冻结模板和规则快照。每个答案字段有原文区间、句子 ID、抽取规则编号；没有字段就不填模板。输出区分已验证短答、原句答案、原文参考、证据不足、歧义和缺少内容；参考保留 `evidence_only` 状态并单列 `mode=reference`，不计入已验证答案。界面展示实际检索词、被过滤表达、事实约束、引用原句与字段高亮；JSON 保留完整过程，CLI 同样输出 `question`、`sentence_evidence`、`answer`。

可直接导入 `data/articles/` 下的短文章摘录及原创测试短文。来源、题目和预期字段见 [短文章验收说明](docs/article-evaluation.md)。离线复跑：

```powershell
python -m evidence.evaluate --output .data/article-evaluation.json
```

## BM25 定义

```text
idf(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))
L(d) = 1 - b + b * dl(d) / avgdl
contribution(t,d) = weight(t) * idf(t) * tf(t,d) * (k1 + 1)
                    / (tf(t,d) + k1 * L(d))
score(q,d) = sum(contribution(t,d) for each unique query term)
```

启用词义扩展时，同组特征只保留最大贡献，其余同组贡献记录为零；完整问题短语覆盖的碎片贡献也记为零。`raw_contribution` 保存组内比较前的加权 BM25 值，`contribution` 保存实际计分值，最终总分严格等于实际贡献之和。人物别名继续使用原规则，词义规则不展开人物名称。表达 TF 来自辅助表中的真实连续区间，长度归一化仍使用正文分词段长；这种混合特征评分公开记录，不等同于修改了正文统计。

默认 `k1=1.5`、`b=0.75`，不是经过准确率调优的参数。`k1` 范围 `(0,10]`、`b` 范围 `[0,1]`，排除 NaN/Infinity。界面每次结果标出**实际使用**的参数；侧栏修改在下一次检索时应用。切分上限和词典修改需重新建索引。

每个候选记录所有查询词，包括未命中词的零贡献、TF、DF、IDF、权重、分子、分母、长度因子、总分及排名。用于排序的分数就是按查询词顺序累加的实际贡献，不另设分数计算路径。展示的小数可能舍入，导出保留 Python 浮点完整往返精度。

## 独立复算与命令行

检索核心和 CLI 只用 Python 标准库，无需安装 Streamlit 即可复算。以下命令在项目根目录运行：

```powershell
# 输出索引文件路径，保存在 .data/indexes/<索引哈希>.json.gz
python -m evidence.cli index data/demo.txt --encoding utf-8 --max-chars 400

# 将 <索引文件> 替换为上一步输出的路径
python -m evidence.cli search "<索引文件>" "什么是信息检索" --export .data/result.json.gz

# 与界面使用同一个复算器；失败时退出码为 1
python -m evidence.cli replay .data/result.json.gz
```

`--export result.json` 生成可直接阅读的未压缩 JSON；`.json.gz` 是 gzip 压缩的同一格式。`index` 还支持 `--dictionary 自定义词典.json`、`--data-dir 存储目录`；`search` 支持 `--k1` 与 `--b`。

`index` 可用 `--book-dictionary 本书词条.json` 补充书籍词条。已有索引无需再次选择原始 TXT，可以从保存的字节重建：

新建索引可用 `--aliases 人工校正.json` 指定人工关系组，默认空；空数组 `[]` 清除人工校正，自动姓名规则继续运行。专用词条重建保留本书人工校正。核心 API 的 `person_config` 可传入完整的 `default_config()` 配置，修改阈值或将 `enabled=False` 关闭自动发现；配置会随索引保存并参与版本计算。

```powershell
python -m evidence.cli rebuild "<索引文件>" --book-dictionary "本书词条.json"
```

关闭一次通用词义扩展进行对比，或导入界面导出的本书表达设置：

```powershell
python -m evidence.cli search "<索引文件>" "赠送" --no-expansion --export .data/literal.json.gz
python -m evidence.cli configure-expansion "<索引文件>" --settings "book-query-expansion.json"
```

设置 JSON 可包含 `config`（`enabled`、`weight`、`max_alternatives`、`max_sources`，可部分提供）、`groups`（表达分组数组）、`blocked`（停用表达数组）。不提供字段时保留当前设置，空数组清空相应校正。语义资源及项目校正在索引中冻结；全局资源更新后需重新导入，或用核心 API 显式传入新的 `expansion_resource`，旧记录继续使用嵌入资源。

“本书词条.json”是纯汉字词数组，例如 `["光合作用", "叶绿体"]`，空数组 `[]` 可清除专用词条，基础词典保留。新索引单独保存。

导出记录包括：问题原文及清洗/分词、原始文件字节（Base64）与 SHA-256、解码后的全文、文件编码、清洗变更与位置映射、切分及词典配置、基础与专用词条、姓名发现候选及接受/拒绝判断、人物上下文与原文位置、自动关系和歧义、人工校正来源、规则资源与阈值、每段实际分词和索引统计、查询位置的全部多字词候选及其词频与选择理由、整词保护与扩展过程、各计分词项的来源与权重、回退来源、查询词表版本、公式与并列规则、原因／方法抽取决策与逐项拒答原因、全部检索候选（不限前五名）及完整计算、最终前五名、版本和完整性哈希。无需原文件、当前词典或已有索引。

复算先校验内容哈希，然后从记录内的原始字节重新解码、清洗、切分，按保存的资源与阈值重新发现姓名、判断关系和歧义，再分词和建索引。比较所有中间结果，重新生成书内词频、查询分词候选和人物关系扩展，计算全部检索候选、词项贡献与最终排名。整数、字符和结构应一致；浮点比较使用绝对/相对容差 `1e-12`。更换姓名规则配置、人工关系、词典、原始字节、编码、切分参数、引擎或 Unicode 数据版本会改变索引标识。

当前引擎为 `evidence-bm25/1.10.0`，新索引与新记录使用 `/11` 格式，兼容 `1.0.0`–`1.9.0` 的 `/1`–`/10` 记录。旧记录使用冻结的历史分词、检索与问答实现复算；新查询从保存字节升级索引。新记录内嵌完整分词词典、初分词频、词义组及来源、通用与本书校正、表达匹配表、参数、姓名与专用词、查询 DAG 与全部扩展判断，不依赖当前安装词典或词义数据复算。辅助表达区间会从原文分词重新生成，全部筛选、贡献与排名重新比较。新记录还包含句子边界、问句提炼、约束、全部候选句、抽取判断、字段位置、原因／方法关系决策、锚点与边界检查及模板快照；复算会重做这些步骤，模板不依赖当前外部文件。新索引单独保存，旧索引和记录保留。不支持的版本明确报错。

文件版本号（原文 UTF-8 内容哈希）、原始字节哈希和索引版本号分别保存。完整性哈希用于发现文件变化；即使重算了哈希，不一致的分词、统计或分数仍会在独立重建时被发现。TF 为零时直接记录零贡献，也避免极小 k1 导致浮点分母下溢的问题。
